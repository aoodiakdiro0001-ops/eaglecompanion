# Eagle Companion (رفيق النسر) — مواصفات التصميم

- التاريخ: 2026-10-19
- الحالة: معتمد من المستخدم
- النطاق: النسخة الأولى (MVP) القابلة للتشغيل والمعاينة

## 1. الملخص

Eagle Companion تطبيق ويب لإدارة الأجهزة الشخصية والعائلية وأجهزة الفريق الصغير، قائم على الموافقة الصريحة والشفافية الكاملة. يتكوّن من لوحة تحكم على الويب ووكيل ويب (PWA) يعمل على الجهاز ويُظهر حالته ويشارك الشاشة فقط عند طلب المستخدم وبإذن المتصفح.

## 2. الأهداف

- تمكين المستخدم من رؤية حالة أجهزته: الاتصال، البطارية، نوع الشبكة، آخر ظهور.
- إدارة مساحات عمل متعددة (شخصية، عائلية، فريق) بأدوار واضحة.
- اقتران جهاز عبر كود لمرة واحدة، وإلغاء الوصول فوراً.
- مشاركة شاشة اختيارية، لحظية، بموافقة صريحة في كل مرة، وغير مسجّلة.
- سجل تدقيق كامل لكل الأحداث الحساسة.
- واجهة عربية RTL احترافية ومتجاوبة.

## 3. غير الأهداف (مستبعد نهائياً)

- أي إخفاء أو تشغيل خفي أو عمل بلا واجهة.
- تجاوز صلاحيات أندرويد أو استغلال إمكانية الوصول (Accessibility) أو الإدارة (Device Admin).
- قراءة الرسائل أو سجل المكالمات أو جهات الاتصال أو الملفات.
- تشغيل الكاميرا أو الميكروفون أو تسجيل الصوت.
- تثبيت APK أو دمج حمولات أو توليد حزم مخادعة.
- التحكم عن بعد بلمس الشاشة أو تنفيذ أوامر على الجهاز.
- تخزين تسجيلات شاشة أو إطارات على القرص.

## 4. المعمارية

- تطبيق واحد Next.js 15 (App Router) + TypeScript يقدّم الواجهة وواجهات API.
- SQLite محلية عبر حزمة `better-sqlite3`، مع إنشاء الجداول تلقائياً عند أول تشغيل.
- Tailwind CSS 3.4 لواجهة RTL داكنة.
- وكيل PWA في المسارين `/pair` و`/agent`، مع `manifest` وService Worker.
- مخزن إطارات في الذاكرة فقط (`Map`) بصلاحية 5 ثوانٍ، وجلسات مشاركة في قاعدة البيانات.
- مصادقة بجلسات مخزّنة في قاعدة البيانات وكوكي HttpOnly، وتجزئة كلمات المرور عبر `scrypt` المدمج.
- تحديد معدل الطلبات في الذاكرة.

### هيكل الوحدات

- `lib/db.ts`: الاتصال، المخطط، الاستعلامات المشتركة.
- `lib/auth.ts`: التسجيل، الدخول، الجلسات، كلمات المرور.
- `lib/tokens.ts`: توليد أكواد الاقتران ورموز الأجهزة وتجزئتها.
- `lib/rate-limit.ts`: نافذة زمنية منزلقة.
- `lib/frames.ts`: مخزن الإطارات المؤقت.
- `lib/audit.ts`: كتابة سجل التدقيق.
- `lib/validation.ts`: مخططات zod.
- `lib/http.ts`: مساعدات الاستجابة، فحص الأصل، استخراج العميل.
- `app/api/*`: مسارات REST.
- `app/(marketing)` و`app/app` و`app/pair` و`app/agent`: الواجهات.
- `components/*`: مكوّنات واجهة قابلة لإعادة الاستخدام.

## 5. نموذج البيانات

| الجدول | الحقول الأساسية |
| --- | --- |
| `users` | id, email (unique), name, password_hash, created_at |
| `sessions` | id, user_id, token_hash (unique), expires_at, created_at |
| `workspaces` | id, name, owner_id, created_at |
| `workspace_members` | workspace_id, user_id, role (owner/member/viewer), created_at |
| `devices` | id, workspace_id, name, platform, model, token_hash (unique), battery_level, battery_charging, network_type, screen_w, screen_h, user_agent, paired_at, last_seen_at, revoked_at |
| `pairing_codes` | id, workspace_id, code_hash (unique), created_by, expires_at, used_at, created_at |
| `invite_codes` | id, workspace_id, code_hash (unique), role, created_by, expires_at, used_at, created_at |
| `share_sessions` | id, device_id, started_at, expires_at, ended_at, last_frame_at, frames_count |
| `audit_logs` | id, workspace_id, actor_user_id, device_id, action, metadata, ip, created_at |

قيود: الأجهزة الملغاة تبقى للسجل مع `revoked_at`، وأكواد الاقتران تُستهلك مرة واحدة.

## 6. واجهات API

### المصادقة
- `POST /api/auth/register` — إنشاء مستخدم ومساحة شخصية وجلسة.
- `POST /api/auth/login` — دخول مع تحديد معدل.
- `POST /api/auth/logout` — إنهاء الجلسة.

### مساحات العمل
- `GET /api/workspaces` — مساحات المستخدم.
- `POST /api/workspaces` — إنشاء مساحة.
- `GET/POST /api/workspaces/[id]/invites` — عرض/إنشاء كود دعوة.
- `POST /api/workspaces/join` — الانضمام بكود دعوة.

### الأجهزة (تتطلب جلسة مستخدم)
- `GET /api/devices?workspaceId=` — قائمة الأجهزة مع الحالة المحسوبة.
- `POST /api/devices/pairing-code` — توليد كود اقتران.
- `GET /api/devices/[id]` — تفاصيل جهاز.
- `DELETE /api/devices/[id]` — إلغاء الجهاز (soft revoke).
- `GET /api/devices/[id]/frame` — أحدث إطار (image/jpeg أو 204).
- `GET /api/devices/[id]/share` — حالة المشاركة.

### الوكيل (تتطلب رمز جهاز Bearer)
- `POST /api/agent/pair` — استهلاك كود الاقتران وإصدار رمز الجهاز مرة واحدة.
- `POST /api/agent/heartbeat` — تحديث الحالة كل 15 ثانية.
- `POST /api/agent/share/start` — بدء جلسة مشاركة (10 دقائق كحد أقصى).
- `POST /api/agent/frames` — رفع إطار JPEG بترميز base64.
- `POST /api/agent/share/stop` — إيقاف المشاركة وحذف الإطار.

### سجل التدقيق
- `GET /api/audit?workspaceId=` — آخر 100 حدث.

## 7. التدفقات

### الاقتران
1. المستخدم يضغط "إضافة جهاز" فيُولَّد كود من 8 محارف (`ABCD-EFGH`) صالح 10 دقائق ولمرة واحدة.
2. الوكيل يفتح `/pair` ويدخل الكود واسم الجهاز.
3. الخادم يتحقق من الكود، ينشئ الجهاز، ويعيد رمزاً عشوائياً 32 بايت مرة واحدة.
4. الوكيل يخزّن الرمز في `localStorage` ويعرض حالة الجهاز.

### النبضة والحالة
- نبضة كل 15 ثانية تحمل البطارية والشحن والشبكة والمقاس.
- الجهاز "متصل" إذا كان `last_seen_at` خلال 45 ثانية، وإلا "غير متصل".

### مشاركة الشاشة
1. المستخدم على الجهاز يضغط "مشاركة الشاشة" ثم يؤكد.
2. `getDisplayMedia` يطلب إذن المتصفح؛ إن لم يدعمه المتصفح تُعرض رسالة واضحة.
3. تبدأ جلسة خادم بصلاحية 10 دقائق، ويُرسل إطار JPEG واحد كل ثانية بعرض أقصى 960 بكسل.
4. لوحة التحكم تعرض الإطار الأخير باستطلاع كل ثانية.
5. يظهر شريط أحمر ثابت وزر "إيقاف المشاركة" على الجهاز، إضافة إلى مؤشر المتصفح.
6. عند الإيقاف أو انتهاء المدة أو إغلاق الصفحة: تُنهى الجلسة ويُمحى الإطار.
7. لا يتم حفظ أي إطار على القرص أو في قاعدة البيانات.

### المساحات والدعوات
- التسجيل ينشئ مساحة شخصية بدور owner.
- المالك ينشئ دعوة بكود صالح 24 ساعة ودور member أو viewer.
- المستخدم المسجّل يُدخل الكود في صفحة الأعضاء للانضمام.

## 8. الأمان والخصوصية

- كلمات المرور: `scrypt` مع ملح عشوائي و`timingSafeEqual`.
- الجلسات: رمز عشوائي 32 بايت، يُخزَّن مجزأً بـ SHA-256، وكوكي `HttpOnly` + `SameSite=Lax` + `Secure` في الإنتاج، مدة 30 يوماً.
- رموز الأجهزة: عشوائية 32 بايت، مجزأة، وقابلة للإلغاء الفوري.
- حماية CSRF: فحص رأس `Origin` لكل الطلبات المتغيرة التي تعتمد الكوكي.
- تحقق مدخلات صارم بـ zod، وتحديد معدل للدخول والاقتران ورفع الإطارات.
- رؤوس أمان: `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, وسياسة محتوى أساسية.
- تفويض على مستوى المساحة والدور لكل قراءة/كتابة.
- سجل تدقيق لا يحتوي بيانات حساسة.
- لا أسرار في المستودع؛ `.env.example` فقط.

## 9. الواجهة

- لغة عربية، `dir="rtl"`، خط نظام مع تحسين قراءة.
- سمة داكنة: كحلي عميق مع لمسات سماوية/زمردية.
- صفحات: الهبوط، الدخول، التسجيل، نظرة عامة، جهاز، أعضاء، سجل التدقيق، إعدادات، اقتران، وكيل.
- مكوّنات: بطاقات إحصائية، شبكة أجهزة، شارة حالة، مؤقت مشاركة، نافذة كود اقتران، خط زمني للتدقيق، تنبيهات.
- إتاحة: تباين كافٍ، حالات تركيز مرئية، تسميات ARIA، دعم لوحة المفاتيح.
- حالات: تحميل، فارغة، خطأ، نجاح.

## 10. الاختبارات

- Vitest للوحدات: تجزئة كلمات المرور، الرموز، تحديد المعدل، انتهاء الإطارات، التحقق.
- اختبارات تكامل مباشرة لدوال قاعدة البيانات: إنشاء مستخدم، اقتران جهاز، إبطال جهاز، صلاحيات المساحة.
- تحقق يدوي: تسجيل، اقتران من المتصفح، نبضة، مشاركة شاشة، إيقاف، تدقيق.
- `npm run build` يجب أن ينجح قبل التسليم.

## 11. التشغيل والنشر

- `npm install` ثم `npm run dev` على المنفذ 3000.
- إعداد `allowedDevOrigins` في `next.config.ts` للنطاق `.monkeycode-ai.live`.
- متغيرات: `SESSION_SECRET` (اختياري للتطوير)، `DATABASE_PATH` (افتراضي `data/eagle.db`).
- معاينة عبر سكربت النشر المحلي.

## 12. معايير القبول

- يمكن التسجيل وإنشاء مساحة والدخول والخروج.
- توليد كود اقتران، اقتران جهاز، وظهوره كمتصل مع بطارية وشبكة.
- إلغاء الجهاز يمنع نبضاته فوراً.
- مشاركة الشاشة تعمل على متصفح يدعم `getDisplayMedia`، مع شريط ظاهر، وتنتهي تلقائياً.
- لوحة التحكم تعرض الإطار الأخير وتختفي عند الإيقاف.
- سجل التدقيق يعرض الأحداث.
- دعوة عضو وانضمامه بدور محدد تعمل.
- الواجهة عربية RTL ومتجاوبة، و`npm run build` ناجح.

## 13. المخاطر وخارطة الطريق

- بعض متصفحات الهواتف لا تدعم `getDisplayMedia`؛ يُكتفى بحالة الجهاز مع رسالة واضحة. وكيل أندرويد أصلي لاحقاً عبر نفس API مع خدمة أمامية ظاهرة.
- التحديث اللحظي حالياً بالاستطلاع كل ثانية/4 ثوانٍ؛ SSE أو WebSocket في نسخة لاحقة.
- الإشعارات الفورية، تصدير سجل التدقيق، ووكلاء سطح المكتب في المراحل التالية.
